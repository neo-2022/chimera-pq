# Phase 3 — Sealed Multi-Hop Transit Proof Plan (revised)

**Status:** in progress — direction corrected after review.

## Decision record

- **Variant B (hidden/internal mechanism) is rejected.** Discovery/mesh
  control-plane must not depend on undocumented behavior.
- **Phase 3 implementation:** option **C** — deterministic in-process
  3-node integration test that proves sealed multi-hop forwarding.
- **Phase 4 design:** option **A** — first-class control-plane route
  announcement (CLI/RPC), designed as a capability-based feature, not a
  test-only hack.

## Phase 3 goal

Demonstrate deterministically that:

1. The planner builds a correct 2-hop lane document when transitive
   reachability hints are present.
2. A sealed stream follows a multi-hop path and survives an intermediate peer
   change.
3. A NAT/destination endpoint correctly decapsulates the stream even though
   the outer route ID and inner destination differ.

## Phase 3 approach

Build an in-process Rust integration test with three mesh nodes:

- **Alice** — source node with a lane to Bob.
- **Bob** — transit node with a lane to Alice and a lane to Charlie.
- **Charlie** — destination node behind NAT (no direct lane from Alice).

The test drives real peer-egress logic but uses in-memory or local TCP
fixtures; no live stand state is touched.

### Evidence checklist

- [x] `chimera-carrier` in-process integration test: Alice sends sealed
      payload; Bob forwards without inspecting; Charlie receives identical
      payload.
- [x] Redacted logs from Bob contain sealed-transit events but **never** the
      plaintext payload (verified by subprocess stderr capture).
- [ ] Lane document generated by planner lists Alice→Bob→Charlie path.
      *Deferred to Phase 4; current test uses shared peer pools and the
      opaque flow-key selector exercised by `select_carrier_binding_*`.*
- [ ] Negative path: if Bob disappears mid-stream, Alice reconnects through
      alternate lane (if configured) or returns a deterministic error.
      *Deferred to Phase 4; the current test proves the happy-path sealed
      multi-hop datapath.*

## Evidence collected

File: `crates/chimera-carrier/tests/multi_hop_sealed_transit.rs`

- `sealed_multi_hop_transit_reaches_destination_unchanged` — Alice→Bob→Charlie
  sealed flow reaches Charlie byte-for-byte unchanged.
- `sealed_multi_hop_logs_do_not_leak_secret` — subprocess stderr capture proves
  transit forwarding events are logged while the secret marker is absent.

Commands run:

```text
cargo test -p chimera-carrier --test multi_hop_sealed_transit  # 2 passed
cargo test -p chimera-carrier -- --test-threads=4             # 245 passed, 2 ignored
```
